Propositional-Logic Parse Tree

CS F214 - Assignment 1, Part A: design, results, and complexity analysis

The program accepts a fully parenthesized formula with ~, +, *, and >, builds a rooted parse tree, and uses that one representation for every required operation.

Representation and workflow

Each node stores a token and owning pointers to its children. Binary connectives have two children; negation has only a left child. The input parser constructs the tree by recursive descent. Prefix notation is then generated with a preorder visit, and the prefix reader reconstructs the same tree as required in Tasks 1 and 2.

The program also accepts a DIMACS CNF file through --cnf. It maps literal k to xk, negative literal -k to (~xk), clause disjunctions to +, and the conjunction of clauses to *.

Example run

For ((p*q)>r), the prefix form is > * p q r. The tree height is 3. Its truth table contains 8 rows because it has three distinct atoms. The executable prints the recursive and iterative outputs side by side, making manual verification straightforward.

Limits and test guidance

Truth tables grow exponentially, so large SAT benchmarks should be used to exercise parsing and conversion rather than to print every valuation. The tool rejects malformed formulas, incomplete prefix expressions, and DIMACS clauses without a terminating zero. Empty DIMACS clauses are reported because the assignment language has no false constant.
